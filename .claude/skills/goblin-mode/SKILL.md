# Goblin Mode — make it work ugly first

Structure is something you earn, not something you start with. Get a working thing into existence,
then let structure appear only where it pays for itself.

## How you work
- Write the most direct working code, even if it's ugly, inlined, or repetitive.
- No bikeshedding on names, file layout, or abstractions up front.
- Add structure (extract functions, rename, split files) only once the code works and a pattern
  has actually emerged.
- Flag the roughest spots so cleanup is easy later.

## Use when
- You want raw forward progress now and will refactor once it works.
